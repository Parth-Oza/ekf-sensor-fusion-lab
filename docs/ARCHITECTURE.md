# Architecture and mathematical model

## State

The filter tracks a planar constant-velocity state:

```text
x = [position_x, position_y, velocity_x, velocity_y]
```

The transition matrix advances position using the current velocity and leaves velocity unchanged. Process noise is generated by mapping independent planar acceleration variance through the elapsed-time model.

## Measurement models

- Position updates observe the first two state components.
- Velocity updates observe the final two state components.
- Each public update accepts an isotropic variance and builds a 2×2 noise matrix.

Measurements can arrive at different rates. The caller controls when to predict and which sensor update to apply, keeping timing semantics explicit.

## Numerical stability

- Kalman gain is computed with `numpy.linalg.solve`, avoiding an explicit inverse.
- Covariance uses the Joseph form after each correction.
- A symmetry guard removes small floating-point asymmetry.
- Invalid time steps and non-positive variances fail immediately.

## Extension path

The current model is intentionally small. Natural extensions include:

- Independent noise covariance per measurement axis.
- Heading, yaw-rate, or acceleration state.
- Nonlinear observation models and angle normalization.
- Innovation gating and outlier rejection.
- Timestamped sensor queues and delayed measurements.
- A ROS2 wrapper that translates messages without coupling middleware to the filter core.

Each extension should include seeded experiments and tests that establish expected behavior.
